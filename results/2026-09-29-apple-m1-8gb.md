# Results: von 1.3 on an Apple M1, 8 GB (2026-09-29)

## Setup

- MacBook with Apple M1, 8 GB RAM, macOS 14
- von-sdk 1.3.1 (weights `wfzyx/von`, von-1.3.0), torch 2.14, Python 3.13, MPS available
- Scripts: `evals/eval_evidence.py`, `evals/probe_tasks.py`

## Performance

| Metric | Value |
|---|---|
| Warm call latency | 0.27 s |
| Resident memory | 1.2 GB (3.6 GB peak while loading) |
| First call | ~76 s (includes the weight download) |
| Batch of 49 decisions | 57 s including model load (~1.2 s each, load amortised) |

## Evidence gate: did a coding agent prove its work?

49 cases. 35 are real results from an autonomous Claude/Codex runner (private, labelled by
hand), 14 are synthetic, mostly "gaming" patterns (claims of verification without output).
Baseline is a keyword regex gate of the kind the runner already uses.

| | regex | von `noul` @ 0.5 |
|---|---|---|
| Accuracy, all | 0.78 | 0.53 |
| Accuracy, real | 0.86 | 0.51 |
| Accuracy, synthetic | 0.57 | 0.57 |
| Unproven results let through | 10/16 | 4/16 |

von's probabilities sat between 0.28 and 0.78 on almost everything, so no threshold
separates the classes. Its highest score (0.78) went to *"Done. Implemented the feature and
verified it works."*, which is exactly the gamed pattern a gate should catch. It lets fewer
unproven results through only because it rejects nearly everything.

## Short intent-style tasks (`choice`)

Run on my original wording; `evals/probe_tasks.py` ships an anonymised copy (personal names,
paths and projects replaced), which reproduces the same scores except where noted.

| Task | Accuracy | Chance | Notes |
|---|---|---|---|
| Prompt feedback tagging (12, incl. German) | 9/12 = 0.75 | 0.25 | misses at 0.88–0.92 confidence: "passt, genau so" (German for "fits, exactly like that") → capability_gap; two neutral prompts → praise / capability_gap |
| Failure triage (9) | 5/9 = 0.56 | 0.20 | anything unfamiliar → `code_error` at 0.7–0.9, incl. HTTP 429 and "Invalid API key" |
| Note relation typing (7) | 3/7 = 0.43 | 0.25 | all answers low confidence. On the anonymised wording shipped in `evals/` it scores 4/7: wording alone moves it |
| Evidence gate as a choice (10) | 8/10 = 0.80 | 0.33 | the 3 answers with confidence ≥ 0.6 were all right; missed two gamed claims |

## What I take from it

1. Speed and memory are fine for a laptop. The quality isn't there yet for acting on it.
2. Calibration is the core promise of this model class, and out of the box it didn't hold on
   my data: several confident answers were wrong. Calibration fitted on the training
   distribution doesn't carry over to a new one.
3. Phrasing matters: the same evidence question went from 0.53 as a yes/no to 0.80 as a
   described multiple choice (different sets, small n, but a big gap).
4. The realistic path is labels from real use, then a fine-tune. Hence shadow mode.

Sample sizes are small. This is a smoke test, not a benchmark.
